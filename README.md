# 麦麦食历（MCD Food Calendar）

> **今天吃什么，让魔盒替你少想一步。**
>
> 你可以告诉魔盒今天的状态、当下的心情和想吃的感觉，也可以什么都不说。
> 魔盒从真实的麦当劳菜单里，找出三个各有理由的选择——少一点纠结，多一点发现。

基于麦当劳中国官方 MCP 开发的参赛作品（1024 程序员节 · 麦当劳程序员创意开发大赛）。
**非麦当劳官方产品**，餐品、价格、供应以官方渠道实时结果为准。

---

## 一、它解决什么

**不是**"如何规划一周饮食"，**不是**营养优化，**不是**减脂工具。

**是**：面对一家店里 100 多个售卖单元、14 个分类，**如何用最低的成本把选择收缩到三个**。

每天发生两次的"中午吃什么、晚上吃什么"，本质不是知识不足，而是**选项过载**——用户不缺"什么健康"的知识，缺的是"现在点哪个"的决断。

所以产品只有一条主线：**减少单次选餐的决策成本**。判断一个功能该不该做，只问一句：它让用户少想一步了吗？

## 二、目标用户

| 用户 | 场景 | 他要的不是 |
|---|---|---|
| 学生（选择多、预算敏感） | 下课后站在食堂门口，"吃啥" | 营养报告 |
| 上班族（午休 40 分钟） | 电梯里 30 秒决定 | 一份 7 天计划 |
| 选择困难 / 今天状态不好的人 | "随便，但别让我更烦" | 被分析心情 |
| 想换口味的人 | 板烧吃了三个月，想试点别的 | 被推荐"更健康"的 |

**明确不作为目标用户**：需要疾病饮食管理、营养治疗或减重方案的人。产品不服务这些需求，也不做相关承诺。

## 三、三个入口，同一个引擎

| 入口 | 用户做什么 | 成本 |
|---|---|---|
| **A 直觉输入** | 点几行情境选项：今天怎么样 / 想吃点什么感觉的 / 有多饿（+ 可选预算、忌口） | 3 次点击，全部可跳过 |
| **B 自由表达** | 说一句话："今天汇报搞砸了，想吃点满足的，别超过 35 元" | 1 句话 + 1 次确认 |
| **C 随机开启** | 什么都不说，直接开盒 | 1 次点击 |

三个入口最后都变成同一个 `Query`，进同一套规则。入口只决定"信息怎么来"。

**关于预算**：默认**不限**。用户没填就不假定他的消费能力——不填预算时，不会用"人均 35 元"这类隐含假设去排序。

**关于状态**：状态只决定"往哪类餐品倾斜"，是一张写死的产品规则表，**不做情绪分析，也不推断营养需要**：

| 你说 | 往哪偏 |
|---|---|
| 累了 | 单手能吃的：汉堡 / 卷 / 小食 |
| 心情不错 | 有点仪式感的：完整套餐、含甜点或饮品 |
| 有点低落 | 热乎扎实的：热食 + 含主食 |
| 想奖励自己 | 贵一点特别一点：高价位带 + 联名/限定/上新 |
| 就想简单解决 | 步骤少的：单品或三件套 |

## 四、三个方案，真的不一样

| 角色 | 回答的问题 | 怎么选出来 |
|---|---|---|
| **懂你款** | 此刻最贴合我的 | 状态词命中 + 感觉标签命中 + 份量匹配 + 主食加分 |
| **稳妥款** | 最不容易选错的 | 搭配完整 + 不是新品 + 价格在本次候选中位数以下 |
| **惊喜款** | 我没想过但可以试试的 | 换品类 + 上新/限定 + 你这次没提过的方向 |

三条规则**各自只看一件事**，不是为了优雅，是为了**一眼能说清为什么是它**。
硬性保证：三个方案的餐品编码两两不同；尽量做到三个品类不同（候选不足时会在卡片上注明"三者同类，因可选范围有限"）。

**每盒都会展开"里面有什么"**：逐项列名称、价格（组合价 or 单点参考价）、每项热量，再给合计热量与"原价/省多少"；主商品配图以像素块形式跟在卡片后面（`mcd_box/enrich.py`）。

**推的是一顿饭，不是一个 SKU。** 单品会按份量自动配成组合：
`垫一下` → 轻量单品；`正常` → 主食 + 小食（或官方套餐）；`很饿` → 主食 + 小食 + 饮品（或官方四件套）。
减脂/清爽时小食优先玉米杯、苹果片，饮品优先无糖/纯饮/柠檬茶；甜一点时优先派、新地、奶铁。
组合价 = 各项真实菜单价相加，超预算自动先减饮品再减小食（`mcd_box/meals.py`）。

## 五、为什么它不是"又一个餐品列表"

1. **主动删掉大部分**：100 多个售卖单元先过份量带、多人餐、非食品（实测联名周边会混在"人气热卖"里）、预算、忌口，最后只给三张卡。
2. **三个角色，不是三个结果**：三款分别回答"此刻想吃什么 / 最稳妥是什么 / 有什么我没试过"。
3. **理由可追溯**：每句理由都只能引用三类事实——你说的话、接口给的数据、实际执行的规则。没有心理分析，没有营养结论。
4. **随机是真的**：`--random` 在符合硬约束的主食池里均匀抽样，同一 seed 完全可复现，不调用任何偏好排序（代码路径可审）。
5. **数据缺失当一等公民**：没价格的餐品不进推荐；营养数据当前版本**不展示**（宁缺不编）；卡片固定标注数据来源与抓取时间。

## 七、数据来源与能力边界

全部业务数据只来自麦当劳中国官方 MCP（`https://mcp.mcd.cn`）。**不抓取、不缓存任何非官方数据源，不使用虚构价格或营养。**

| 能力 | 工具 | 实测事实 |
|---|---|---|
| 门店搜索 | `query-nearby-stores` | `city + keyword` 必须同传；返回 `distance`；**经纬度恒为 0** |
| 菜单 + 现价 | `query-meals` | 单店 106 个售卖单元 / 14 分类；`data.meals` 自带名称、图片、现价、原价、优惠类型 |
| 价格校验 | `calculate-price` | 单位是**分**，支持批量；与菜单现价 18/102 不一致（10-21 实测样本）（未应用会员优惠），仅用于改单重算 |
| 营养 | `list-nutrition-foods` | 160 条，**无产品 code，只能按中文名匹配**（抽样 84.8%）→ 当前版本不参与推荐，也不展示 |

已知边界（都会直接影响用户体验，所以写在这里）：

- **"菜单里有" ≠ "这家店现在一定有"**：接口不返回库存与售罄状态。
- **忌口只能按名称/分类匹配**，没有成分表，也不含交叉接触信息；过敏请向门店核实。
- **价格以门店实际为准**：菜单价是会员/促销后的现价，与核价接口存在差异。
- **营养数据不完整**：因此本版本不把热量/蛋白作为推荐依据，也不在卡片上编造数字。
- 不支持外送、得来速、点餐支付——本作品只做"选"，不做"买"。

## 九、项目结构

```
├── mcd_box/
│   ├── mcp_client.py    # JSON-RPC over streamable HTTP
│   ├── adapter.py       # 在线/缓存/快照三源统一，按 code 去重；套餐子项带缓存
│   ├── candidates.py    # 候选标注：份量带、上新、人气、多人餐、周边、主食
│   ├── meals.py         # 把单品凑成"一顿饭"（主食 + 小食 / + 饮品）
│   ├── recommend.py     # 硬过滤 + 懂你/稳妥/惊喜 + 差异化 + 随机
│   ├── entry.py         # 三入口 → Query；L0 文本解析 + 回显
│   ├── nutrition.py     # 营养表快照 + 名称归一 + 逐项匹配（匹配不到=未知）
│   ├── enrich.py        # 渲染前补全：明细 / 热量 / 单点价 / 原价 / 配图
│   ├── render.py        # 卡片 / JSON
│   └── cli.py           # 命令行入口
├── server.py            # 本地网页服务（标准库 http.server，含 CORS）
├── web/index.html       # 像素风单页：三问 + 开盒 + 三卡 + 会话式调整
├── start_web.cmd        # Windows 双击启动器
├── scripts/
│   ├── verify_chain.py      # 验证菜单与核价链路，产出数据报告
│   ├── build_snapshot.py    # 抓真实菜单存离线快照
│   ├── build_details.py     # 抓套餐子项（43 个套餐）
│   ├── build_nutrition.py   # 抓官方营养表（160 条）
│   ├── smoke_candidates.py  # 候选池体检
│   └── probe_*.py           # 早期接口探针（保留了失败记录）
├── tests/test_rules.py  # 19 项规则测试（含组合价、热量一致性）
├── data/snapshot/       # 离线快照（带抓取时间）
├── docs/                # PRD、变更日志、实施计划、数据链路报告
├── skill/SKILL.md       # WorkBuddy 技能工作流
└── raw/                 # MCP 原始返回（过程证据，含失败与异常样本）
```

## 十一、合规与免责

- 本项目不抓取任何外部数据，不存储用户个人信息；Token 只通过环境变量读取，仓库内不含任何真实凭证。
- 营养信息（如有展示）仅供参考，不构成医疗或营养专业建议；本产品不提供疾病饮食或治疗性饮食建议。
- 餐品、价格、活动、库存均以麦当劳官方渠道实时结果为准。
- 本作品为个人参赛项目，非麦当劳官方产品。
